# 2603. 출처와 언어에 독립적인 근거 기반 주제 추론 채택

## Context and Problem Statement

문서 계층과 명시적 참조를 표시하는 지식 그래프만으로는 여러 문서의 연관 내용을 모아 탐색하기 어렵습니다. 현재 로컬 위키뿐 아니라 메타데이터, 헤더, 폴더, 태그, 링크가 없는 일반 노트북도 같은 규칙으로 처리해야 합니다. 사용자는 특정 문서 서비스의 어댑터와 언어에 따른 분기를 배제한 설계를 확정하고 구현을 요청했습니다.

## Decision

ADR 2504의 레지스트리에 `topicInference` 확장을 추가합니다. 기본 지식 그래프의 노드, 관계, 분류 및 물리 계산은 변경하지 않습니다.

1. 추론기는 불투명한 문서 ID와 본문 구간을 받습니다. 제목과 원문 위치는 표시용이며 헤더, 참조는 선택 정보입니다. 특정 출처의 필드, 언어 판별, 사전, 고정 업무 분류, 외부 모델 및 네트워크 요청을 사용하지 않습니다.
2. 동일한 Unicode 정규화와 3·6문자 구간을 모든 입력에 적용합니다. 특징 구간은 단어·셀 경계를 넘지 않습니다. 문서 내용별 출현 빈도로 반복 서식의 영향을 낮추고, 해당 구간에 있는 참조만 본문 일치의 보강 근거로 활용합니다. 문자열 일치를 의미의 동일성으로 확정하지 않습니다.
3. 같은 본문은 근거 집계에서 한 번 처리하고 원문 위치를 모두 보존합니다. 문서 정체성을 합치거나 원본 노트를 수정하지 않습니다. 메타데이터나 제목만으로 복제본을 판단하지 않습니다.
4. 희소 역색인에서 구간별 최대 4개 독립 문서 후보를 비교합니다. 후보 점수에서도 중첩 문자 창을 중복 집계하지 않습니다. 모든 주제 구성원 사이에 비교된 일치 근거와 하나의 공통 본문 문구가 있어야 하므로 연결을 따라 전체 노트북을 한 묶음으로 확장하지 않습니다. 공통 문구별 후보를 검사해 구간당 최대 3개 초안 묶음을 만들고, 승격 기준을 통과한 묶음만 주제로 게시합니다. 여러 주제에 참여할 수 있으며 근거가 부족하면 미분류로 남깁니다.
5. 주제 이름은 모든 구성원이 공유하는 본문 근거에서 선택하며 대표 문서의 제목이나 개별 업무 행을 그대로 사용하지 않습니다. 여러 공통 문구를 조합한 이름은 문구별 근거를 보존합니다. 구분이 어려운 이름에는 원문 한 구간의 예시를 별도로 표시하여 묶음 전체의 공통 설명으로 오인하지 않도록 합니다. 사용자는 이름 변경, 제외, 숨기기, 분리, 병합 및 초기화를 수행할 수 있습니다. 사용자 모음과 자동 추론은 구분하고, 선택 사항은 계정·모드·노트북별 AsyncStorage와 React Query 키로 격리합니다.
6. 메뉴 버튼에서는 계산하지 않습니다. 활성 화면에서만 생성기를 약 4ms 단위로 실행하고 화면 이탈, 비활성화, 노트북 변경 시 취소합니다. HTML 추출은 본문 전체 문자열과 참조 대상 목록을 비교해 재사용합니다. 원문·참조 목록이 같으면 추론도 재사용하고 변경 시 노트북 전체 빈도와 후보를 다시 평가하여 삭제 및 빈도 변화를 반영합니다. MessageChannel을 사용할 수 없으면 타이머로 제어권을 반환합니다.
7. 이스케이프된 HTML은 문단 전체에서 해제하여 Markdown 문단 사이에 나뉜 표도 처리합니다. 표의 행·셀 경계를 유지하고 코드 예시의 HTML은 보존합니다. 주제와 미분류는 같은 읽기 가능한 본문을 사용하며 원본 HTML 속성을 추론하지 않습니다.
8. 겹친 3·6문자 창을 최대 공통 문구로 합치고, 가중치는 겹치지 않는 문자 구간의 정보량과 실제 일치 위치의 합집합으로 계산합니다. 단일 짧은 단어는 앞뒤 본문 구간에서 추가로 일치하는 내용이 필요합니다. 문맥은 최대 3개 독립 본문에서 앞뒤 각 240문자만 지연 추출하며 제목·메타데이터는 사용하지 않습니다. 반복된 고정 문구 사이의 서로 다른 실질 대상이 두 곳 이상이면 연결을 거절하고, 숫자만 달라진 버전은 대상 충돌로 취급하지 않습니다.
9. 구성원 역색인에서 겹친 묶음을 최대 32개씩 확인합니다. 포함 관계, 60% 이상의 겹침 또는 같은 핵심 문구의 겹친 묶음을 정리합니다. 승격 이후에는 같은 핵심 문구의 별도 묶음도 핵심 문구 역색인에서 최대 32개씩 찾아 검증합니다. 이 단계는 이미 승격한 묶음에만 적용하여 약한 후보를 합친 뒤 반복성을 부풀리지 않습니다. 통합 후 최대 25개 구성원의 모든 쌍에 독립 본문 일치가 필요하며, 초기 후보 제한 때문에 비교하지 않은 쌍은 같은 검증기로 확인합니다. 두 정리 단계가 공유하는 추가 비교 예산은 전체 구간 수 이하이며 초기 비교와 합쳐 최대 구간 수의 5배 이내를 유지합니다. 예산이 부족하거나 한 쌍이라도 검증되지 않으면 병합하지 않습니다. 묶음 ID는 정렬된 구성원 내용 ID의 서명으로 만들고, 게시 직전에 같은 구성원 서명을 중복 제거합니다.
10. 동일 HTML의 문단·본문 조각과 동일 절대 참조를 실행 내에서 재사용합니다. 상대 참조는 원문 제목을 기준으로 해석하고 600문자 조각별 실제 앵커에만 연결합니다. 링크가 없는 본문에는 불필요한 DOM 파싱을 하지 않습니다. 전체 본문을 정확하게 비교해 같은 내용의 빈도 집계 객체도 재사용합니다. 분석 캐시에 알고리즘 버전을 포함하되 사용자 선택 저장 범위는 유지합니다.
11. 단순 구간 일치를 노트북 주제로 바로 승격하지 않습니다. 독립 본문 수 `F`에 대해 기본 반복 기준은 `min(4, max(2, ceil(log2(max(1, F)) / 2.5)))`입니다. 표시용 대표와 각 구성원 사이에 가중치 0.65 이상, 24 Unicode 문자 이상의 공통 문구가 있으면 작은 묶음도 유지합니다. 독립 본문 3개 이상에서 추가 공통 문구가 있고 대표 근거 가중치가 모두 0.35 이상이면, 해당 공동 문맥의 절반 이상을 설명하는 구체적인 묶음도 유지합니다. 모든 승격 후보는 핵심 문구 및 최대 두 보강 문구가 함께 나오는 독립 본문의 25% 이상을 설명해야 합니다. 희소 특징의 문서 집합에서 실제 정규화 본문을 확인해 빈도를 계산하며 언어·출처별 예외를 두지 않습니다. 더 구체적이거나 같은 수준의 주제가 작은 주제의 모든 내용을 포함하면 해당 중복을 정리합니다. 전체 주제 수를 고정 개수로 자르지 않습니다.

12. 이름이 중복된 주제만 보강 명칭을 찾습니다. 모든 구성원에 있는 원문 문구의 앞·중간·끝과 셀·문장 경계에서 최대 72문자 후보를 만들고 주제별 최대 48개를 평가합니다. 같은 이름의 비교 대상은 정렬된 최대 64개로 제한하며, 묶음 구별 가능성·독립 본문 빈도·간결성을 함께 사용합니다. 짧은 기존 핵심명은 보강 문구와 조합해 유지하고 숫자 위주의 짧은 서식만으로 대체하지 않습니다. 독립적인 두 공통 문구의 조합도 평가하며 `nameFragments`는 각 문구의 본문 근거를 보존합니다. 같은 이름이 남으면 최대 8개 구성원의 제한된 원문 창에서 구분되는 예시를 선택해 구성원 ID와 함께 보존하고 목록·상세 화면에 **본문 예시**로 표시합니다. 예시가 가리키는 구성원을 제외하면 예시도 제거합니다. 사용자 이름과 모음에는 자동 명명 규칙을 다시 적용하지 않습니다. 표시 문자열에 번호나 해시를 붙여 고유함을 꾸미지 않으며 언어·출처별 규칙을 사용하지 않습니다.

## Consequences

- 기존 `Content`와 확장 등록, React Query, AsyncStorage 및 문단 탐색을 사용하므로 저장 형식 마이그레이션과 새 의존성이 없습니다.
- 공통 서식 억제와 보수적인 후보 제한 때문에 같은 의미를 다른 표현으로 기술한 내용을 놓칠 수 있습니다. 원문 근거와 미분류 탐색을 제공하고, 확률 형태의 신뢰도를 표시하지 않습니다.
- 본문 전체가 변경되면 주제 및 구간 ID도 달라질 수 있습니다. 변경하지 않은 구간의 ID는 내용 기반으로 유지되며 파일 이동, 표시 언어 및 메타데이터 변경에 영향을 받지 않습니다.
- 큰 노트북에서는 독립 본문 두 개의 약한 일치가 주제로 게시되지 않을 수 있습니다. 원문 위치와 검색용 텍스트는 미분류에서 유지하고 사용자가 만든 모음에는 자동 승격 기준을 적용하지 않습니다. 문자 길이·가중치·빈도 기준은 휴리스틱이며 의미 정확도를 보장하지 않습니다.
- 협력적 실행의 4ms는 단일 DOM 파싱·정렬·GC 시간을 포함하는 절대 상한이 아닙니다. 큰 노트북의 실제 브라우저 작업 시간과 취소 동작을 검증해야 합니다. 그래프 화면에는 추론 작업이 남지 않도록 화면 활성 조건을 검사합니다.

## Implementation Plan

- `apps/notebook/src/features/topicInference/types.ts`: 출처 독립 입력, 원문 위치, 주제 및 근거 타입.
- `inferTopics.ts`: 순수 생성기, Unicode 문자 특징, 독립 내용 빈도, 후보 색인, 서로 일치하는 구성원, 사용자 정리 적용.
- `topicEvidence.ts`: 최대 공통 문구, 원문 표기 보존, 일치 위치 중복 제거 및 본문 문맥 충돌 검사.
- `topicNames.ts`: 중복명 구분, 공통 보강 문구의 구성 요소 및 원문 예시; 협력적 실행과 비교 범위 제한.
- `extractTopicDocuments.ts`: 기존 HTML 문단, 모든 헤더 레벨, 헤더 없는 구간과 참조 추출; 정확한 원문 비교 캐시 및 삭제 정리.
- `runTopicTask.ts`, `useTopicInference.ts`: 짧은 작업 단위와 취소, 현재 노트북 및 프라이버시 범위, 선택 사항 영속화.
- `TopicInferenceScreens.tsx`, `TopicInferenceButton.tsx`, `features/index.tsx`: 근거·원문·미분류·정리 화면과 기존 확장 등록.
- `apps/notebook/src/lang/ko.json`, 한국어 `사용 방법.md`, 영어 `Usage.md`: UI 번역과 사용 방법. 화면 언어는 분석기 입력에 포함하지 않습니다.
- `__tests__`: 메타데이터 없는 문서, 문자 치환, 이동, 복제본, 공통 서식, 브리지 연결, 수정·삭제, 원문 추출, 스코프 격리, 사용자 정리, 취소 및 후보 수 증가율.
