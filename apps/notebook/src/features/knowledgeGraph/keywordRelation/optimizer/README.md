# 관계 분석 최적화

이 폴더는 관계 후보의 원문·역할 보존, 중복 추론 방지, assistant 직접 판독을 통한 오판 측정을 담당한다. 개별 판독과 비교 데이터는 세션 메모리에서 관리한다. `.runs` 폴더는 생성하지 않는다.

특정 노트·개체·관계명·헤더명·문장 패턴에 정답이나 예외를 지정하지 않는다. TS·CJS·JSON 모두 같은 기준을 적용한다. 원문에서 추출한 관찰과 assistant가 직접 판독한 결과는 평가 자료이며, 앱의 예외 목록으로 사용하지 않는다. 테스트의 가상 입력과 점수도 실제 노트북의 정답이나 측정 결과로 사용하지 않는다.

## 적용한 다섯 변경

### 1. 대조 입력과 본문 판정 분리 — validation.ts

본문 의미 판정 `semantic`과 관계 역할 확인 `eligibility`를 별도로 기록한다. 대조 개체를 임의의 개체 목록에서 가져오지 않는다. 전체 관찰에서 같은 역할로 실제 등장한 다른 값을 안정적인 키 순서로 선택한다. 노트 순서가 바뀌어도 같은 대조를 고른다.

대조 점수 차이는 직접 판독 자료에서 보정한 `controlMargin`이 있을 때만 사용한다. 대조가 없거나 실행에 실패하거나 판정이 불확실하면 본문의 지지를 취소하지 않는다. optimizer 실행기는 대조 실행 오류를 `controlError`에 기록하고 본문 원시 점수를 재사용한다. 다음 실행에서 누락된 대조만 다시 계산할 수 있다.

예를 들어 본문이 `작업 A의 담당은 사람 B`를 지지하더라도, 관계없는 사람 C를 대입한 문장의 점수가 높다는 사실만으로 B의 관계를 취소하지 않는다. 보정에는 같은 역할의 실제 대조와 assistant 판독이 필요하다.

### 2. 구문 결과에 의한 후보 삭제 제거 — claims.ts / syntax.ts

병렬 논항·명사 복합어라는 구문 분석 결과만으로 후보를 삭제하지 않는다. 구문 분석의 역할·상태·보류 사유는 후보에 남는다. 파서가 없거나 실패한 것도 관계 부재의 증거가 아니다.

`두 서비스가 서로 통신한다`와 `두 서비스를 점검한다`는 병렬 형태가 같아도 관계 타당성이 다르다. 특정 접속사나 상호 표현의 단어 목록으로 정답을 지정하지 않는다. 식별자의 부분 단어를 개체로 오인하지 않도록 경계를 확인하는 기존 처리는 유지한다.

### 3. 표의 주체 단정 제거 및 대상별 근거 — tables.ts / schema.ts / role-evidence.ts

고유 값이 많은 열을 주체로 확정하지 않는다. 가능한 행의 역할 조합을 후보로 보존하고, 원래 노트·상위 문단·표·행·출발 열·대상 열·대상 개체의 셀 내부 위치를 함께 남긴다. 여러 사람이 있는 셀도 사람마다 별도의 가설과 위치를 가진다. 원본 셀 전체는 근거에 남겨 계획·부정·조건을 완료 사실로 바꾸지 않는다.

`작업: 이전 예정 / 담당: 사람 A·사람 B`의 두 대상은 각자 검사한다. `제품 A의 기능 / 제품 B의 기능`의 값을 같은 행에 있다는 이유로 확정하지 않는다. 원본 값의 위치 확인과 두 열 사이의 의미 관계 확인은 서로 다르다.

역할 보정은 직접 판독한 자료의 열 위치·열 수·값의 고유도·온전한 값의 비율·구문 상태 등 수치 특징으로 선형 판별 계수를 계산한다. 노트명·개체명·헤더명·문장 패턴을 조회하는 허용표는 없다. 복사 문서군을 하나의 독립 평가 단위로 묶으며, 각 문서군을 빼고 학습한 예측으로 채택 기준을 보정한다. 양성·음성 판독이나 독립 문서군이 부족하면 역할을 확정하지 않는다. 학습 범위를 벗어난 특징도 보류한다.

역할 판정기는 실행 시 판독 자료에서 계산해 메모리에만 둔다. JSON/CJS에 미리 작성한 규칙이나 JSON에서 역직렬화한 역할 정책은 받지 않는다.

`roles.minValidRetention`은 문서군별 정상 관계 회복률의 평균과 전체 고유 정상 관계 회복률에 모두 적용하는 최소 기준이다. 작은 문서군의 평균이 높아도 관계가 많은 문서에서 대부분을 놓친 정책은 생성하지 않는다. 정밀도 하한과 두 회복률을 만족하는 구간 중 전체 고유 관계 회복률이 가장 높은 구간을 고른다. `insufficient` 판독도 확정 채택할 수 없는 자료로 보정에 포함하며, 의미상의 중립·모순 정답으로 바꾸지는 않는다.

같은 노트·문단·개체쌍·근거·역할의 반복 위치는 하나의 관계로 센다. 반복 관찰은 해당 관계의 학습 가중치를 나눠 가지며 회복 건수를 늘리지 않는다. 같은 관계에 타당·부적합 판독이 충돌하면 보정을 중단한다. 교차 검증에서 임계값을 고르는 비교와 실제 판정의 비교는 동일한 부동소수점 오차 허용을 사용한다. 계산 반올림 수준의 점수 차이만으로 긍정·부정 사례를 나누지 않는다. 요약의 `validRetention`은 문서군 평균, `caseValidRetention`은 전체 고유 관계 회복률이며 두 지표를 혼용하지 않는다.

### 표 제목 복원 — corpus.ts

서수형 열 이름을 가진 표에서 구분용 빈 행 다음에 실제 제목 행이 올 수 있다. 첫 번째 완전한 행까지만 확인하고, 앞에 구분 행이 있었다면 노트북의 실제 Markdown 헤더 배열과 순서가 일치하는 근거가 있어야 제목을 복원한다. 같은 제목 행이 표 안에 반복되어도 데이터 개체쌍으로 만들지 않는다. 헤더명 목록을 소스에 지정하거나, 값의 고유도만으로 주체를 정하지 않는다.

파싱 캐시는 원본 구조를 보존하고 제목 복원은 매번 복사본에 수행한다. 근거가 되는 노트가 제거되면 복원 결과도 재검토한다. 전체 문서 처리 중 취소 확인과 이벤트 양보를 유지한다.

### 명시적 필드 목록과 문서 주체 — corpus.ts / tables.ts / validation.ts

필드 값 전체가 하나 이상의 Markdown 링크로 이루어졌을 때 실제 토큰의 링크 경계를 사용한다. 단일 링크도 목록과 동일한 주체·값 보존 조건을 적용한다. 빈도 사전에 없는 링크가 포함되어도 다른 완전한 항목을 잃지 않는다. 설명·조건·다른 일반 텍스트가 끼어 있으면 목록으로 축약하지 않는다. 링크의 실제 위치를 검사하므로 앞에 같은 평문이 있어도 링크와 혼동하지 않는다.

이 명시적 목록의 현재 문서는 자신의 필드 주체이므로 제목 빈도가 낮아도 출처가 있는 문서 주체로 포함한다. 다른 문서 본문의 평문을 링크나 노트 식별자로 해석하지 않는다. 값 자체는 기존 키워드 사전을 사용하며 새 이름을 임의로 만들어 넣지 않는다.

앱과 최적화 실행기가 공유하는 `prepareRelationValidation`에서 완전한 필드 값의 포함 관계와 원문 자기 복사를 구분한다. 위치가 확인된 필드는 기록된 역할을 지지하며, 자기 복사만으로 관계 의미를 확정하지 않는다. 원시 모델 점수는 보존하며 점수 자체를 정답으로 고치지 않는다.

### 4. 자기 재구성과 의미 추론 분리 — validation.ts / analysis.ts

`verification.kind`는 `semantic`, `record-membership`, `source-reconstruction`이다. optimizer 실행기는 원문 복사와 원본 셀·필드의 값 확인에 NLI를 호출하지 않으며, 가짜 NLI 확률도 만들지 않는다. 자기 복사에 높은 과거 점수가 있어도 그것만으로 관계를 지지하지 않는다. 독립 지지 수와 평균 의미 점수에도 가산하지 않는다.

원본 값의 위치가 맞더라도 표의 두 역할이 타당한지 확인되지 않았다면 보류한다. 의미 추론을 생략했다는 사실은 오판 감소를 입증하지 않는다. 후보 보존율과 실제 판독 결과를 별도로 측정해야 한다.

실험 실행 경로는 `optimizer/analysis.ts`다. 앱 기준 검증은 상위 `relationAnalysis.ts`의 결과를 사용하며 두 실행기의 판정·호출 수를 혼용하지 않는다. 모델·입력이 같은 원시 점수는 판정 정책 변경과 별개로 재사용한다.

### 5. 판정 건수 우선 보정 제거 — verdict-evaluation.ts / review-calibration.cjs

분류별 정밀도의 Wilson 95% 신뢰구간 하한과 최소 판정 비율·최소 건수를 만족하는 후보 중 오판 위험 상한이 낮은 정책을 선택한다. 판정 건수가 많다는 이유로 오판 위험이 높은 정책을 고르지 않는다. 부족한 자료에서는 정책을 생성하지 않는다.

의미 판정은 지지·중립·모순의 세 분류다. 확신 부족은 정답 분류가 아니라 보류 상태다. 복사된 근거는 중복 투표하지 않고, 같은 노트와 복사 근거를 연결한 문서군이 보정·평가 양쪽에 들어가지 않게 한다. 기준 오판이 0이면 감소율은 계산 불가로 남긴다. 이미 예측을 본 평가군은 독립 평가 성과로 보고하지 않는다.

## 전수 판독과 측정

검증용 모델을 다운로드하거나 실행하지 않는다. 정답은 assistant가 노트 원문·문단·개체쌍·가설을 직접 읽고 기록한다. 원문 복사, 개체 부재, 특정 단어를 근거로 코드가 정답을 자동 작성하지 않는다.

메모리 측정에서는 `prepareReview`, `checkedJudgments`, `reportReview`에 객체를 직접 전달한다. 파일 입출력 CLI는 기존 자료 호환용이며, 파일 출력을 요청한 경우에만 다음 형식으로 사용한다. 출력 경로는 저장소 밖으로 지정한다.

앱 기준 결과는 `application-evaluation.cjs`의 `runApplicationEvaluation(notes, options, load?)`로 수집한다. 앱의 실제 `relationAnalysis.ts`를 호출하고 반환된 관찰·최종 판정 객체를 그대로 사용한다. 최적화 전용 실행기나 후보 내보내기의 결과로 재판정하지 않는다. 기본 점수 저장소는 메모리이며 `scope`는 명시해야 한다. 매니페스트에는 실행 경로·노트 해시·소스 해시·모델·정책·완료 여부를 남기고, 주입한 런타임을 구분한다. CPU 대체 재실행과 실행 중인 브라우저의 GPU 결과도 구분해 보고한다.

```sh
node apps/notebook/src/features/knowledgeGraph/keywordRelation/optimizer/run-corpus.cjs \
  /path/to/notebook /tmp/relation-review/current
```

`run-corpus.cjs`는 전체 후보를 추출한다. 이 출력은 앱 최종 판정 결과가 아니다. 임베딩·NLI 추론과 표본 한도가 없다. `manifest.json`에는 노트·소스 해시와 전체 관찰 수가 남는다. 다른 코드 버전과 비교할 때는 같은 노트북 스냅샷의 결과를 사용한다.

`census.cjs prepare <config.json>`은 결과 데이터셋들의 모든 관찰과 가설의 합집합을 내보낸다. 설정에는 `output`, `notebookRoot`, `datasets`의 이름·디렉터리만 필요하다. 설정 경로는 입출력을 지정하며 정답이나 예외 규칙을 포함하지 않는다. 판독 자료는 모델 점수·기존 판정·대조 점수를 숨기며, 원본 Markdown 문서와 해시를 포함한다.

assistant는 메모리의 판독 객체에 결과를 기록한다. 각 결과에는 내보낸 `id`·`contentHash`, `reviewer: assistant`, `reviewedAt`, `expectedLabel`, `sourceClarity`, `relationJudgment`, `reason`, 실제 원문의 `evidenceQuotes`가 필요하다. 의미 정답과 개체쌍의 관계 타당성을 따로 판단한다. 모호하거나 주장 문장이 아니면 의미 정답은 `null`이다. 읽지 않은 사례는 추가하지 않는다. 파일 CLI를 명시적으로 사용하는 경우에만 같은 객체를 `assistant-judgments.json`으로 주고받는다.

`census.cjs report <config.json>`은 직접 판독된 자료만 집계한다. 최적화가 제거한 관찰도 비교 분모에서 빠지지 않는다. 미판독이 있으면 전수 상태는 완료가 아니며 전체 오판율·정밀도는 `null`이다. 일부 판독의 지표는 `reviewed...`로 구분한다.

`semantic.byVerdict`와 `relationship.byVerdict`는 각각 의미 판정과 최종 관계 판정을 지지·중립·모순·확신 부족·미검증별로 집계한다. 지지·중립·모순에는 판정 수, 판독 수, 미판독·원문 불확정 수와 TP·FP·FN·TN을 포함한다. 최종 지지에서는 문장 의미가 지지여도 직접 판독에서 파싱 오류나 단순 동시 등장으로 확인된 관계를 FP로 센다.

- `falseDiscoveryRate`: 해당 판정 중 틀린 비율, `FP / (TP + FP)`이다.
- `falsePositiveRate`: 실제 해당 클래스가 아닌 사례를 잘못 분류한 비율, `FP / (FP + TN)`이다.
- 미판독이 남으면 전수 비율은 `null`이며, 판독·평가 가능한 부분의 비율만 `reviewedFalseDiscoveryRate`·`reviewedFalsePositiveRate`로 제공한다. 원문 불확정은 정답으로 세지 않는다. 해당 판정 안에 불확정이 있으면 전수 `falseDiscoveryRate`가, 비교 모집단에 불확정이 있으면 전수 `falsePositiveRate`가 `null`이다. 분모가 0인 비율도 `null`이다.
- 확신 부족·미검증도 명확한 원문 판정을 놓쳤다면 `missedDecisions`로 오류에 포함하고, `missedByExpectedLabel`로 놓친 지지·중립·모순을 집계한다. 의미 판정에서는 직접 판독으로 의미가 확정된 사례를, 최종 관계 판정에서는 타당한 지지 및 명확한 중립·모순을 놓친 사례를 센다. 파싱 오류·단순 동시 등장 후보를 지지하지 않은 경우는 `nonActionable`로 분리하며, 원문 불확정은 `unresolved`로 남긴다. 기존 `knownSemanticLabels`와 `heldValid`·`heldValidRate`도 제공한다.
- 각 판정의 `confirmedErrors`는 확인된 오류 수이며, 지지·중립·모순에서는 FP, 확신 부족·미검증에서는 판정 누락 수다. `errorRate`는 해당 판정 중 오류 비율이다. 미판독이나 원문 불확정이 있으면 확정 비율은 `null`이다. 판독이 끝났지만 불확정이 남으면 `confirmedErrorRate`로 확인된 최소 오류 비율을, `errorRateBounds`로 불확정이 모두 맞거나 모두 틀렸을 때의 범위를 표시한다. 확신 부족·미검증의 통계적 FP 비율은 여전히 `null`이며 판정 누락 오류 비율과 구분한다.

`semantic.overallError`와 `relationship.overallError`는 잘못된 확정 판정(`wrongDecisions`)과 확신 부족·미검증의 판정 누락(`missedDecisions`)을 합산한다. 전체 오류율의 분모에는 미판정도 포함된다. 확정 판정만의 정확도(`decisionAccuracy`)와 전체 오류율을 함께 보며, 불확정 사례를 정답으로 간주하거나 누락을 제외해 전체 오류가 0이라고 보고하지 않는다.

의미 판정 통계는 실제 의미 검증 대상에 한정한다. NLI가 필요 없는 셀·필드 포함 관계 및 원문 재구성 검사는 `semantic.notApplicable`로 분리한다. 이때 NLI를 실행하지 않은 것을 의미 판정 누락으로 세지 않지만, 최종 관계 판정이 타당 관계를 보류했다면 `relationship.overallError`에는 누락으로 포함한다.

이 구조 검증 사례에는 `expectedLabel: null`, `sourceClarity: not-applicable`로 의미 정답을 생략할 수 있다. 타당 관계 여부는 여전히 assistant가 원문을 직접 판독한다. 구조 검증의 타당 관계를 보류하면 의미 라벨 없이도 최종 관계의 판정 누락·회복률에 반영한다. 실제 의미 검증 사례에는 이 표기를 허용하지 않는다. 같은 개체쌍·문장이라도 관계 역할이 다르면 별도 관계로 집계하며, 같은 역할과 내용의 반복 관찰은 고유 관계 분모에서 중복 가산하지 않는다.

`census.cjs calibrate <config.json>`도 전수 판독이 끝나기 전에는 정책을 만들지 않는다. 추가 설정 `calibration`에는 대상 `dataset`, 평가군 비율 `holdoutFraction`, 역할 보정의 `roles.minFamilies`·`minPrecision`·`minValidRetention`, 의미 보정의 `semantic.targetPrecision`·`minCoverage`·`minPerClass`를 지정한다. 이 값은 평가 요구 수준이며 특정 관찰의 정답이 아니다. 대조 보정은 선택적 `controls.minPrecision`·`minDecisions`·`minCoverage`를 사용한다.

`calibrateReviewedPacket`은 같은 모듈 로더를 마지막 인자로 받을 수 있다. 기준을 통과한 역할 판정기는 반환값의 `runtimePolicy`로 즉시 검증에 전달할 수 있다. 의미 분류 자료가 부족해도 역할 보정 결과를 버리지 않는다. `runtimePolicy`는 JSON 직렬화에서 제외하며 정책은 자동 적용하지 않는다.

앱 실행기도 후보 생성 직후 `prepareResultValidations(result, policy)`를 호출한다. 따라서 명시적으로 전달한 `nli`·`roleEvidence` 정책이 앱의 최종 판정에 적용된다. 정책을 전달하지 않은 앱에 세션의 판독 자료나 학습 결과를 자동 주입하지 않는다.

역할 보정은 요구 정밀도와 두 최소 회복률을 통과하는 구간 중 전체 고유 관계 회복률이 가장 높은 구간을 선택한다. 동률이면 문서군 평균과 정밀도의 신뢰 하한을 차례로 비교한다. `roleCalibration.diagnostics`에는 학습·교차 검증 건수, 고유·타당 관계 수, 확보한 최고 정밀도 하한, 요구 정밀도에서 가능한 문서군 평균·고유 관계 최대 회복률과 탈락 사유를 남긴다. 판독이 충분해도 요구 성능을 내지 못한 경우를 단순 자료 부족과 구분하며, 이 수치는 별도 평가군의 성과가 아니다.

### 오판과 전체 판정 타당성의 동시 평가

`assessComparison(report, before, after, targets)`에는 `minPrecision`, `minDecisionAccuracy`, `minValidRetention`, `minDecisionCoverage`를 명시한다. 지지 판정의 정밀도와 함께 지지·중립·모순 전체 확정 판정의 정확도를 계산하며, 미판정과 근거 불충분을 정답으로 세지 않는다. 제거된 타당 후보를 포함한 합집합이 회복률의 분모이며, 중복 후보는 정상 관계 회복 수를 늘리지 않는다. 채택했지만 근거가 불충분한 결과도 확정 정밀도의 분모에서 빼지 않는다.

정밀도·확정 판정 정확도·정상 관계 회복률·전체 판정 비율 중 하나라도 기준 미달이면 실패다. 미판독 사례가 있으면 비교를 완료하지 않는다. 의미 판정 비율이 줄었거나 기존 의미 오류가 없으면 의미 오판 감소율은 계산하지 않는다. 정상 관계 회복률이 줄어든 경우 거짓 지지 감소율도 계산하지 않는다. 오류 후보 제거와 최종 판정 오류 감소는 별도로 보고한다.

비교의 `errorReductionRate`는 확정 오판과 타당 관계의 보류·미검증 누락을 합친 최종 관계 오류 감소율이다. NLI 의미 판정만의 감소율은 `semanticErrorReductionRate`로 구분한다. 원문·역할·가설이 같은 전체 검증 모집단에서만 최종 감소율을 계산한다. 후보를 제거하거나 가설을 바꿨다면 기존 모집단에 대한 감소율은 `null`이고 `finalErrors.status`는 `changed-population`이다. 누락 후보는 기존 합집합 회복률에서 계속 평가한다.

원문 불확정 사례는 정답으로 간주하지 않는다. 전후의 불확정 사례와 판정이 같으면 같은 미지의 오류 기여분으로 묶고, 감소율의 가능한 범위를 `errorReductionRateBounds`에 남긴다. 불확정 판정까지 바뀌면 두 오류 범위에 대해 보수적으로 계산한다. 정확한 감소율을 확정할 수 없으면 `errorReductionRate`는 `null`이다. 선택적 `targets.minErrorReductionRate`를 지정하면 그 범위의 하한도 목표를 만족해야 채택 조건을 통과한다. 확인된 오류만의 감소율은 `finalErrors.confirmedErrorReductionRate`이며 실제 감소율과 혼용하지 않는다.

`verdict-review.cjs`의 수치 보고·비교 기능과 `evaluate.cjs`의 과거 관계 결과 보고는 유지한다. 기존 표본 추출 및 점수만으로 하는 관계 임계값 보정은 제거했다. 정상적인 새 보정 진입점은 원문·assistant 판독·해시를 확인하는 `census.cjs`다.
