# 2602. 지식 그래프 뷰 확장 기능 아키텍처

## Context and Problem Statement

노트와 보드가 늘어나면 문서 계층, 카드·문단, 내부 참조와 외부 링크의 관계를 한눈에 파악하기 어렵습니다. 기존 저장 형식을 바꾸지 않고 현재 모드의 데이터를 탐색하고 검증할 화면이 필요합니다.

## Decision

`apps/notebook`은 `knowledgeGraph` 확장에서 현재 모드의 노트·보드를 읽어 그래프를 구성합니다.

1. **노드와 관계**
   - 기본 노트·외부 링크 분류와 보드별 분류를 표시합니다. 노트·보드 문단·카드·일반 문단·외부 링크는 각각 개별 노드입니다.
   - 노트 경로와 문단 계층의 포함 관계, 내부 참조, 외부 링크 및 분류 소속 관계를 구분합니다. 카드 헤더는 카드 노드 하나로 표현하고, 같은 보드에서 이름이 같은 보드 문단은 출처를 보존하면서 하나로 합칩니다.
   - 본문이 없는 노트는 제외합니다. 내용이 있는 노트가 직접 참조하거나 바로 위 경로에 사용하는 기존 빈 노트는 구조를 잇는 노드로 유지합니다.
2. **화면과 검증**
   - HTML5 2D Canvas와 포스 시뮬레이션으로 그래프를 그립니다. 노드 선택 시 `1`, `2`, `전체` 범위의 관계를 탐색합니다. 일반 문단과 일반 외부 링크의 표시를 각각 전환할 수 있습니다.
   - 참조 무결성과 고립 노드를 현재 애플리케이션 규칙으로 검사하고, 영향을 받은 노드를 화면에서 찾을 수 있게 합니다. 노트의 YAML frontmatter 값은 상세 시트의 메타데이터 칩으로 표시합니다.
   - ADR 2504의 확장 등록 규격을 따라 `features['knowledgeGraph']`에 연결하고 한국어 `사용 방법.md`와 영어 `Usage.md`를 함께 유지합니다.

## Consequences

- Good: 저장 형식 마이그레이션 없이 문서 구조와 참조를 탐색할 수 있습니다.
- Tradeoff: 큰 그래프의 렌더링과 레이아웃 비용을 관리해야 하므로 인접 목록, Canvas 렌더링 및 포스 시뮬레이션의 성능 검증을 유지합니다.

## Implementation

- **Data construction**: `useKnowledgeGraphData.ts`에서 현재 모드의 노트·보드를 읽고 관계를 구성합니다. `utils/axioms.ts`에서 검증을 계산합니다.
- **Presentation**: `KnowledgeGraphView.tsx`와 `canvasRenderer.ts`는 화면에 표시할 노드·관계를 처리하고, `KnowledgeGraphPreviewSheet.tsx`는 상세정보와 원본 노트 탐색을 제공합니다.
- **Documentation**: `apps/notebook/public/사용 방법.md`와 `apps/notebook/public/Usage.md`에 진입, 탐색, 보기 옵션 및 빈 노트 처리 규칙을 기록합니다.

## More Information

### 2026-09-29: 같은 노드 쌍의 관계명 레이블 분리

같은 두 노드 사이에 유형이 다른 관계가 여러 개 있으면 중점에 그린 관계명 레이블이 완전히 겹칩니다. `canvasRenderer.ts`는 표시할 레이블을 연결 방향과 무관하게 노드 쌍별로 묶고 관계 ID 순서로 정렬한 뒤, 각 레이블을 두 노드의 중점에서 세로 18px 간격으로 배치합니다. 레이블 박스 높이가 13px이므로 인접 박스 사이에는 5px 간격이 남습니다. 관계가 하나뿐이면 중점에 그대로 표시합니다.

구현 위치는 `apps/notebook/src/features/knowledgeGraph/utils/canvasRenderer.ts`이며, `apps/notebook/src/features/knowledgeGraph/__tests__/knowledge-graph-canvas.test.cjs`에서 정방향·역방향 관계, 가로·세로 노드 쌍, 단일 관계를 검증합니다. 그래프 회귀 테스트 66개와 TypeScript 검사가 통과했습니다.

### 2026-09-30: 외부 링크 토글 시 줌 유지

`외부 링크`(`External Links`) 토글로 일반 외부 링크 표시를 전환할 때 새 링크 노드가 추가되어도 자동으로 화면 맞춤을 실행하지 않습니다. `KnowledgeGraphCanvasView.tsx`는 최초 그래프 배치 때만 자동 화면 맞춤을 적용하고, 토글에 따른 레이아웃 재시작과 시뮬레이션 종료 시에는 줌을 재조정하지 않습니다. 선택한 노드의 중앙 이동과 사용자가 줌 HUD의 `화면 맞춤`을 직접 누르는 동작은 계속 제공됩니다.

### 2026-09-30: 최상위 노트와 선택 범위 중심 배치

노트 계층의 거리 기준은 노트 클래스가 아니라 `INSTANCE_OF`로 노트 클래스에 속하면서 다른 노트에 포함되지 않은 최상위 노트 인스턴스 각각입니다. 보드 계층은 기존처럼 보드 클래스가 기준입니다. 보드 노트의 하위 노트는 최상위 노트로 취급하지 않고 해당 보드에 남깁니다. 노트 클래스와 외부 링크 클래스는 분류 노드로 표시하되 노트 계층을 끌어당기는 중심축으로 사용하지 않습니다.

노드 선택 후 연관 범위가 `1` 또는 `2`이면 화면에 표시되는 연결 노드를 선택 노드 쪽으로 우선 배치합니다. 직접 연결된 노드와 2-hop 노드는 각각 선택 노드에서 약 135px, 250px을 목표로 하며 노드 간격 배율을 적용합니다. 해당 노드의 평상시 계층 거리 제약을 선택 중에만 완화합니다. `전체`로 바꾸거나 선택을 해제하면 우선 배치를 제거하고 기존 시뮬레이션의 뿌리 위치를 유지한 채 평상시 배치로 돌아갑니다.

구현은 `utils/forceLayout.ts`의 뿌리 거리 계산과 `setSimulationFocus`, `components/KnowledgeGraphCanvasView.tsx`의 선택 범위 갱신에 둡니다. `knowledge-graph-large-graph.test.cjs`에서 여러 최상위 노트·보드 자손의 소속, 1·2-hop 우선 배치, `전체` 전환 후 복귀를 검증합니다.

### 2026-09-30: 문단과 일반 외부 링크의 원형 배치

뿌리가 가까울 때 모든 자손을 가장 가까운 뿌리의 영역 안으로 강제로 투영하면 문단과 일반 외부 링크가 영역 경계에 줄지어 쌓입니다. `forceLayout.ts`는 이 두 유형을 소속 뿌리의 거리 스프링과 충돌 힘으로 배치하고, 해당 뿌리·거리 단계의 문단과 일반 외부 링크를 유형별로 원 둘레에 고르게 초기 배치합니다. 문단에는 일반·보드·연결 문단을 포함하며, 다른 구조 노드의 영역 제약은 유지합니다. 가까운 뿌리 사이에서는 원형 분포를 위해 일부 문단·링크가 가장 가까운 뿌리 영역을 넘을 수 있습니다.

`knowledge-graph-large-graph.test.cjs`는 가까운 두 최상위 노트가 있을 때 두 유형의 사분면 분포와 경계 부근 밀집을 검증합니다.

### 2026-09-30: 외부 링크 클래스의 인스턴스 중심 배치

외부 링크 클래스는 화면에 표시된 일반 외부 링크와 연결 외부 링크 인스턴스 전체의 좌표 평균에 놓습니다. 시뮬레이션을 시작할 때와 매 단계가 끝날 때 중심을 다시 계산하므로 노트·보드 쪽 링크의 분포가 바뀌어도 클래스가 실제 인스턴스들의 중심을 따릅니다. 일반 배치에서는 외부 링크 클래스를 충돌 반발·중력 계산에서 제외하고 분류 소속(`INSTANCE_OF`) 관계도 배치력으로 사용하지 않아 링크 인스턴스의 노트·보드 기준 배치를 유지합니다. 링크가 하나뿐이면 클래스와 링크의 클릭 영역이 겹치지 않도록 클래스만 링크 옆으로 최소한 이동합니다.

이 기준은 앞서 사용한 노트 클래스 근처 또는 노트·보드 클래스 사이의 외부 링크 클래스 고정 위치를 대체합니다. 구현 위치는 `utils/forceLayout.ts`이며 `knowledge-graph-large-graph.test.cjs`에서 일반·연결 외부 링크의 중심과 단일 링크의 클릭 가능 거리를 검증합니다.

### 2026-09-30: 선택 범위의 연결 노드 인력 강화

연관 범위 `1` 또는 `2`에서 멀리 있는 연결 노드가 보드 소속 연결과 다른 자손 노드의 힘 때문에 선택 노드에서 충분히 가까워지지 않는 경우가 있었습니다. 선택 노드 쪽 인력을 `0.065`에서 `0.32`로 높이고, 기존 1-hop·2-hop 목표 거리(각각 135px·250px) 안에 이미 있는 노드에는 밀어내는 힘을 적용하지 않습니다. `전체` 범위에서는 이 인력을 적용하지 않습니다.

`knowledge-graph-large-graph.test.cjs`는 자손 노드가 많은 먼 보드 노트가 선택 시 충분히 가까워지는지와 연관 범위 해제 후 기존 배치로 돌아가는지를 검증합니다.

### 2026-09-30: 시뮬레이션 중 선택 노드 중앙 유지

선택 노드를 화면 중앙으로 옮기는 애니메이션의 목적 좌표를 선택 당시 위치로 고정하면, 연관 노드 재배치 과정에서 선택 노드 자체가 움직여 중앙에서 벗어납니다. `KnowledgeGraphCanvasView.tsx`는 포스 시뮬레이션의 각 프레임 뒤에 선택 노드의 최신 좌표를 읽어 중앙 이동 애니메이션의 목적지를 갱신합니다. 초기 이동이 끝난 뒤에도 시뮬레이션이 계속되면 노드 좌표에 맞춰 카메라 위치를 갱신하며, 시뮬레이션이 끝나는 프레임까지 선택 노드를 상세 시트 위의 가용 화면 중앙에 둡니다. 사용자가 직접 화면을 이동하거나 확대·축소하면 자동 추적을 중단합니다.

`knowledge-graph-canvas.test.cjs`는 이동 중 목적지 갱신, 애니메이션 종료 후 중앙 유지, 수동 조작 시 추적 중단을 검증합니다.

### 2026-09-30: 클래스 기점 BFS 연결선 강조

화면에 표시된 노트 클래스와 모든 보드 클래스를 동시에 시작점으로 하여 관계선을 양방향으로 BFS 탐색합니다. 탐색 방향은 저장된 관계 방향과 독립적이며, 순환·중복 관계가 있어도 각 연결선은 순회별로 한 번만 진행합니다. 일반·연결 외부 링크 인스턴스(`EXTERNAL_LINK`, `CONNECTED_EXTERNAL_LINK`)는 강조의 종점입니다. 링크로 들어오는 효과는 진행하되 링크에서 다음 노드로 나가는 효과는 생성하지 않습니다. 여러 문서가 같은 링크를 참조하면 문서별 도착 효과는 각각 진행합니다.

### 2026-10-01: 연결선 강조의 렌더링 비용 관리

`KnowledgeGraphCanvasView.tsx`는 강조 전용 캔버스를 사용해 정지한 그래프 전체를 다시 그리지 않습니다. 픽셀 배율은 최대 1.5, 강조 갱신은 최대 25fps로 제한하고 대기 중에는 타이머를 사용합니다. `canvasRenderer.ts`는 컨텍스트·테마별로 캐시한 그라데이션 이미지를 재사용하며 프레임별 그라데이션 생성과 흐림 그림자를 사용하지 않습니다. 진행 중인 선분만 관리하고, 긴 비활성 기간 이후에는 완료된 순회를 건너뛰되 아직 진행 중인 중첩 순회는 복원합니다.

### 2026-10-01: 연결선 강조 보기 토글

`KnowledgeGraphView.tsx`의 `연결선 강조`(`Highlight Edges`) 토글은 기본값이 `true`입니다. 끄면 강조 캔버스를 지우고 순회 상태와 애니메이션 예약을 해제하며, 다시 켜면 현재 노트·보드 클래스부터 새 순회를 시작합니다. 토글은 레이아웃·줌·선택 노드의 카메라 이동을 변경하지 않습니다. 운영체제의 움직임 감소 설정이 켜져 있으면 강조를 표시하지 않습니다.

### 2026-10-01: 도착 후 순차 강조와 고정 속도 이동

연결선 하나 안에서는 등속으로 이동합니다. 100% 줌 기준 초기 속도는 600px/초이며 BFS 단계마다 60px/초씩 감소해 최저 300px/초를 유지합니다. 이동 시간은 노드 경계 사이에서 빛의 길이를 제외한 이동 거리에 비례합니다. 화면상 속도와 빛의 크기는 줌 배율에 비례하며 줌 변경만으로 진행률이나 도착 시점은 바뀌지 않습니다.

빛의 기본 길이는 32px이며, 짧은 연결선에서는 노드 사이에 들어가도록 줄입니다. 최소 표시 크기는 화면 기준 8×1px입니다. 머리는 선명하게 유지하고 꼬리 끝으로 갈수록 투명해지는 그라데이션을 적용합니다. 최소 길이 보정은 꼬리에만 적용해 머리가 실제 도착 위치를 따르게 합니다.

각 노드의 최초 도착 즉시 후속 연결선을 시작하고 다른 경로의 도착을 기다리지 않습니다. 종점 규칙을 적용해 도달 가능한 모든 노드를 한 번 이상 방문하면 기존 순회를 유지한 채 새 순회를 즉시 추가합니다. 시작 클래스는 출발 시 방문한 것으로 처리하고, 고립 노드와 외부 링크를 거쳐야만 도달할 수 있는 노드는 완료 기준에서 제외합니다. 순회마다 방문 기록을 분리해 이전 순회의 도착이 새 순회에 영향을 주지 않게 합니다. 모든 도착 시간이 0인 경우에만 무한 반복 방지를 위해 시작 간격을 300ms로 둡니다.

`graphTraversal.ts`가 BFS 계획·순회별 도착 기록·시간순 이벤트를 관리합니다. `knowledge-graph-traversal.test.cjs`에서 탐색 방향, 외부 링크 종점, 개별 도착과 중첩 순회, 속도·줌·머리 위치, 긴 비활성 기간 및 캐시 이미지 재사용을 검증합니다.

### 2026-10-10: 큰 그래프의 물리 계산 비용과 프레임 점유 감소

`forceLayout.ts`는 모든 노드 쌍의 최소 거리를 저장하던 배열을 노드별 충돌 속성·소속 루트 색인으로 대체합니다. 기존 반발력의 최대 거리와 같은 크기의 공간 격자를 매 스텝 갱신하여 주변 셀의 쌍만 검사합니다. 거리 제한, 클래스·루트·포커스의 충돌 거리, 중첩 좌표 분리, 루트 인력과 속도 제한을 유지하며 힘을 근사하거나 노드를 생략하지 않습니다. 위치·속도와 후보 색인은 재사용하는 숫자 버퍼로 처리하고, 충돌이 없는 쌍은 같은 반발력 식을 제곱 거리로 계산합니다.

`KnowledgeGraphCanvasView.tsx`는 반발력 계산에 6ms 양보 기준을 적용하여 이어지는 애니메이션 프레임에서 남은 계산을 처리합니다. 한 스텝이 끝났을 때만 좌표와 냉각 계수를 반영하며, 계산 중 확대·이동은 현재 좌표로 다시 그립니다. 마지막 좌표 갱신과 실행 환경의 GC 비용 때문에 이 기준은 프레임 시간의 상한을 보장하지 않습니다. 선택 범위 변경은 미완료 계산을 버리고 현재 충돌 우선순위를 반영합니다.

임시 Node 벤치마크에서 기본 표시와 전체 표시 각각의 초기화, 60스텝의 중앙값·95백분위, 숫자 버퍼 크기, 분할 호출 시간을 Git 인덱스의 소스와 비교하고 물리 계산의 CPU 표본을 확인했습니다. 같은 로컬 폴더에서 기본 표시(3,971노드)의 초기화는 1,174ms에서 31ms, 스텝 중앙값은 108ms에서 6.8ms로 줄었습니다. 전체 표시(9,557노드)는 초기화 12,632ms에서 69ms, 스텝 중앙값 658ms에서 34ms로 줄었으며, 분할 호출의 95백분위는 약 9.5ms였습니다. 전체 표시의 숫자 버퍼는 174.2MiB에서 0.41MiB로 감소했습니다. 이 값은 Node에서 측정한 물리 계산 비용이며 캔버스 그리기와 브라우저 FPS를 포함하지 않습니다.

그래프·대시보드 데이터의 SHA-256 비교는 변경 전과 일치했습니다. `knowledge-graph-simulation-performance.test.cjs`는 전체 쌍 계산과 공간 격자의 힘 비교, 음수 좌표·거리 경계·중첩 위치, 클래스·루트·포커스 규칙, 분할 계산 일치와 중간 좌표 비노출, 선택 변경, 9,500노드 메모리 증가율, 계산 중 줌과 냉각 시점을 검증합니다. 앱 회귀 테스트 474개가 통과했습니다.

### 2026-10-10: 전체 9,557노드의 캔버스 그리기 비용 감소

`forceLayout.ts`는 공간 셀의 노드 색인을 연속 배열에 오름차순으로 저장하고 이진 탐색으로 이미 처리한 쌍을 건너뜁니다. 후보 배열 복사 없이 주변 셀의 범위를 순회하며, 노드 유형별 객체 속성 순서를 통일하고 같은 충돌·반발력의 누적을 합칩니다. 힘의 거리 제한과 충돌 규칙을 유지합니다. 같은 전체 그래프의 Node 물리 스텝 중앙값은 앞선 약 34ms에서 약 25ms로, 6ms 분할 호출의 95백분위는 약 6.1ms로 줄었습니다.

`canvasRenderer.ts`는 줌 0.22 미만에서 1,000개 이상의 노드·관계가 있으면 같은 스타일끼리 경로를 묶습니다. 그룹은 테마와 배열별로 재사용하되 현재 좌표와 화면 범위는 매번 읽습니다. 모든 원과 관계선을 유지하며 선택·호버·검증 경고는 기존 상세 표시로 그립니다. 노드 6,000개 이상에서 배치 계산 중에는 연결선 강조를 쉬고, 배치가 끝나면 같은 BFS 계획으로 새 순회를 시작합니다.

실제 로컬 노트북의 9,557노드·18,082관계·경고 45개를 포함한 전체 보기에서 `fill`·`stroke` 호출은 28,557회에서 279회로 감소했습니다. 별도 임시 프로필의 헤드리스 Chrome에서 GPU를 끄고 1,200×800 소프트웨어 캔버스의 그리기와 `getImageData` 완료 시간을 측정했습니다. 같은 좌표·스타일로 Git 인덱스의 렌더러와 현재 렌더러를 번갈아 실행하고 5회 준비 후 각각 20회 측정하여 중앙값 366.9ms → 76.9ms, 95백분위 455.5ms → 104.7ms를 확인했습니다. 이 조건은 실제 앱의 GPU 화면 FPS 측정이 아닙니다.

검증용 오프라인 HTML은 노트 내용을 읽기만 하고 제목 길이를 유지한 익명 레이블과 숫자 ID를 사용했습니다. 렌더러만 Git 인덱스에서 읽어 같은 현재 배치와 비교했습니다. 검증에 사용한 HTML과 브라우저 프로필은 측정 후 제거했습니다.

`knowledge-graph-simulation-performance.test.cjs`는 전체 쌍 계산과의 수치 비교 외에도 전체 보기의 원·관계선 수, 포커스 투명도, 경고·선택 표시, 현재 좌표·테마 반영, 9,557노드 배치 중 강조 중단과 완료 후 재시작을 검증합니다. 앱 테스트 477개, TypeScript 및 변경 파일의 ESLint 검사가 통과했습니다.

### 2026-10-10: 초기·토글 후 노드 이동의 12fps 검증

전체 9,557노드의 초기 진입과 표시 토글 직후 이동은 정지 화면 그리기 시간과 구분하여 검증합니다. 물리 계산이 끝난 프레임에만 좌표를 표시하면 6ms 분할 호출 사이에 화면이 멈추므로, `KnowledgeGraphCanvasView.tsx`는 노드 6,000개 이상에서 표시 좌표를 별도로 두고 정확한 물리 좌표 쪽으로 시간에 따라 이동시킵니다. 계산 예산은 호출당 12ms이며 냉각 계수는 완성된 스텝에만 적용합니다. 첫 정확한 목표는 초기 화면을 표시하기 전에 준비하고, 배치 종료 시 모델 좌표와 정확히 맞춥니다. 클릭 판정과 선택 카메라는 표시 좌표를 사용하며, 토글 도중 재배치는 현재 보이는 위치에서 이어집니다.

이동 중 Canvas 비트맵은 최대 960×540 픽셀·DPR 1로 제한합니다. 픽셀 반지름 0.75 미만인 일반 노드는 면적을 반영한 점으로, 다른 노드는 스타일별 캐시 이미지로 그립니다. 이미지는 픽셀 좌표에서 그려 불필요한 이미지 변환을 피하며, 캐시는 현재 노드 배열과 배율에 한정합니다. 관계선은 스타일별로 묶되 경로당 최대 256개로 나누고, 이동 중 점선·화살표·관계명 장식을 쉬게 합니다. 모든 노드·관계와 선택·호버·검증 경고의 상세 표시를 유지합니다. 마지막 좌표는 이동용 화면으로 먼저 표시한 다음 좌표가 바뀌지 않는 프레임에서 원래 해상도와 상세 장식을 복원합니다.

익명화된 오프라인 이동 검증 HTML을 별도 임시 Chrome 프로필에서 실행했습니다. 실제 컴포넌트의 훅 fixture, 포스 시뮬레이션, Canvas와 `requestAnimationFrame`을 함께 실행하고 배치 완료까지 좌표가 바뀐 화면의 완료 간격을 기록했습니다. 1×1 픽셀 읽기로 그리기 완료를 확인하여 매 프레임 전체 화면을 읽는 인위적인 대량 할당을 피했습니다. 각 프레임 간격이 1,000/12ms 이내인지 확인하고 노드·관계선 비용도 분리하여 진단했습니다. 사용자의 요청에 따라 검증용 CJS 스크립트는 저장소에서 제거했으며, 위 측정은 당시 결과 기록입니다.

GPU를 끈 헤드리스 Chrome의 1,920×1,080·DPR 2 조건에서 기본 연결선 강조 설정을 포함하여 검증했습니다. 초기 이동의 620개 프레임 간격 중 최대는 48.7ms(최소 20.5fps), 전체 토글 후 624개 간격 중 최대는 57.9ms(최소 17.3fps)로 모두 12fps 기준을 통과했습니다. 1,600×900·DPR 2의 별도 전체 이동 검증도 초기 665개 간격 최대 52.9ms, 토글 후 781개 간격 최대 49.3ms로 통과했습니다. 초기 생성·준비 비용과 좌표가 바뀌지 않는 정지 화면 복원은 이동 FPS에 포함하지 않습니다. 이 결과는 위 검증 환경의 컴포넌트 측정이며 모든 장치·브라우저 부하에서의 절대적인 FPS 하한을 뜻하지 않습니다. 실제 로컬 노트북의 노드·관계·경고 수와 그래프·대시보드 SHA-256 비교는 유지됩니다.

`knowledge-graph-simulation-performance.test.cjs`는 계산 중 실제 표시 좌표 갱신, 모델 불변과 정확한 최종 좌표, 해상도·장식 복원, 캐시 이미지 재사용, 9,557개 픽셀 점 보존, 관계 경로 크기 제한을 검증합니다. 앱 테스트 481개, TypeScript 및 변경 파일의 ESLint 검사가 통과했습니다. 앱만 수정하여 저장소 규칙에 따라 빌드는 생략했습니다.
